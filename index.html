The customer sends an order.The request includes a stable request ID.
  1. 01 / CUSTOMER

    Start with the request.

    The customer places an order. The request includes a stable ID. A retry will use the same ID.

  2. 02 / ORDER API

    Save before you charge.

    The API creates a pending operation. It stores a payment key with the request ID. The store enforces a unique request ID for each customer.

  3. 03 / PAYMENT SERVICE

    Charge with the saved key.

    The API sends the payment key to the payment service. The service uses this key to identify the operation.

  4. 04 / FAILURE

    The response is lost.

    The charge succeeds. The API stops before it saves the result. The stored operation still says “pending.”

  5. 05 / RETRY

    Find the first operation.

    The customer retries with the same request ID. The API reads the pending operation and gets its original payment key.

  6. 06 / RECOVERY

    Recover the result.

    The API retries with the same payment key. Under the service’s idempotency rules, it gets the existing result. It saves the result and confirms the order.

    If the key has expired, the API must reconcile the charge before it starts a new operation.
